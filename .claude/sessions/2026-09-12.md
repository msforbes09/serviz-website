# v1 polish pass

Scope agreed with the user up front: visual polish and motion, plus fixing what
was already weak. Explicitly **not** in scope: new sections, new copy, splitting
the single scroll into multiple pages.

## Shipped

Defects, all reproduced in a browser before being fixed:

- **Permits row on a phone.** Three fixed columns squeezed each card to about
  110px and the labels spilled outside their own dashed borders. Now two
  columns below `sm`.
- **Hero headline.** Three hard `<br>` tags plus a 36px floor gave six lines on
  a phone, two of them half width. Breaks removed, `text-balance` added, floor
  lowered to 32px.
- **Hero headline column.** The heading carried `max-w-[680px]` but the grid
  only ever gave it 552px, so 60px type broke into six ragged lines on desktop
  too. The text column now takes `1.6fr` above 900px, which is the 680px the
  markup always asked for. Five full lines at the same type size.
- **Headline could vanish.** It is a gradient clipped to the glyphs, so the text
  itself is transparent. Forced-colours modes drop background images and would
  render nothing. Solid-colour fallback added under `forced-colors: active`.
- **Mobile menu was a visual overlay only.** Now a real disclosure: focus moves
  in on open and back to the toggle on close, Escape dismisses, Tab cycles
  inside it, and the page behind does not scroll.
- **Contact form.** Declared itself both `role="alert"` and `aria-live="polite"`.
  Now a single polite status region that stays in the accessibility tree. The
  failed field is marked invalid, described by the message, and receives focus.
- **No skip link.** Added, first in the tab order.
- **Anchor jumps** landed under the sticky nav. `scroll-mt-20` on every target.

Polish:

- Card grids stagger their reveal by index instead of arriving as one block.
- The sticky nav lifts off the page once you scroll, via a scroll timeline with
  no JavaScript and no `from` keyframe, so it degrades to the flat bar.
- One focus ring for the whole layout, scoped by `.v1-root`.

## Gotchas hit

- **A JSX comment cannot sit between `return (` and the root element.** It reads
  as a second child. `{/* ... */}` there is a parse error, not a lint warning —
  put it above the function instead.
- **Programmatic `.focus()` does not reliably match `:focus-visible`**, so
  checking a focus ring that way gives a false negative. Send a real Tab key.
- **`validateConsultation` now returns the field at fault**, not just a message.
  Two existing assertions used `toEqual` and had to take the new key.

## Verified

`npm run build` green, which covers lint and 53 tests. Checked in the browser at
375px and 1440px: hero line breaks, permits grid, nav shadow appearing on
scroll, staggered reveal ranges, skip link on first Tab, form error state. v2
and v3 rendered unchanged.

# v1: devices borrowed from e.gov.ph

Reviewed https://e.gov.ph at the user's request. Vite SPA, Tailwind, Framer
Motion, brand blue `#0040E7`. Took four devices, in v1's own palette. Left the
hero stat line out: it needs numbers the cooperative has not given us, and the
rule is that we do not invent facts.

## Taken

- **Two-tone headlines.** Every heading now ends with its payoff phrase in
  orange. This replaced the gradient-clipped hero headline, which read as
  texture rather than emphasis and which needed a `forced-colors` rescue
  precisely because it made the text itself transparent. That rescue is deleted.
- **Connected steps.** How it works was three bordered cards that said nothing
  about sequence. Now numbered nodes on a hairline that fades at both ends,
  running between the first and last node centres, gone once the columns stack.
- **Icon ramp.** The seven service icons stepped from forest to orange via
  `color-mix(in oklab, ...)` driven by the card index. Every tint is a blend of
  the two brand colours, so the ramp cannot drift off-brand no matter how many
  cards get added.
- **Pointer spotlight.** `SpotlightCard` writes the cursor position to two
  custom properties and CSS draws the gradient, so a mousemove repaints one
  gradient and re-renders no React.

## Deliberately not taken

- **Their reveal mechanism.** Framer Motion writes inline `opacity: 0` on every
  below-fold element and waits on an observer. That is the pattern that left our
  own hero blank in a background tab. v1's scroll-driven CSS costs no JavaScript
  and fails to visible.
- **Their reduced-motion story.** Zero `prefers-reduced-motion` rules in their
  stylesheet. Everything added here sits inside the existing guards.
- **Their rendering model.** One client bundle, no server HTML. v1 stays fully
  prerendered; `SpotlightCard` takes its contents as children so the cards
  remain server-rendered.

## Gotchas hit

- **The Browser pane's coordinate frame is not the emulated viewport.** With a
  1440x900 viewport the frame was 800x500, so hover coordinates read off a page
  measurement have to be scaled or they land outside the frame.
- **A sibling overlay paints above non-positioned content**, so the glow sits
  over the card text rather than behind it. Fine at 9% alpha, verified legible,
  and the same thing e.gov.ph does at 13%.

## Anchor navigation

- **Smooth scrolling**, global rather than v1-only at the user's direction, since
  v2 and v3 should behave the same way as they are built out. Inside the
  reduced-motion guard: someone who asked for less movement gets the browser's
  instant jump.
- **Landing position corrected.** `scroll-mt-20` from the polish pass double
  counted: the nav is 69px, the scroll margin was 80px, and every section
  already carries 80px of its own top padding, so a jump left a 91px dead band
  under the nav. Dropped to `scroll-mt-8`, which lands the first line 43px below
  the nav. Confirmed by the scroll position moving exactly 48px, the difference
  between the two margins.

All seven targets share the same section padding, so one value fits them all.
If a section's padding ever changes, this needs revisiting with it — **and it
since has.** The spacing pass took section padding to 96px and the margin to
`scroll-mt-4`, keeping the same 43px landing. See the arithmetic section below.

# Carrying the v1 pass over to v2 and v3

Everything above describes what was done to v1. This section is the part worth
re-reading before touching another variant: what transfers unchanged, what has
to be re-measured per variant, and what is deliberately v1-only.

Scope agreed for v1 was **visual polish plus repairs**, explicitly not new
sections, new copy, or splitting the single scroll into pages. Agree the same
boundary again before starting, because "enhance v2" is as open-ended as
"enhance v1" was.

## Check every variant for these seven defects

All seven were found in v1. None were unique to it in principle, so check rather
than assume. Reproduce each in a browser before fixing; three of them looked
fine in the code and only showed up on screen.

1. **Grids with a fixed column count at every width.** v1's permits row held
   three columns down to 375px, crushing each card to ~110px and pushing labels
   outside their own borders.
2. **Hard `<br>` in a headline.** Only holds at the width it was designed for.
3. **A heading whose `max-w-*` exceeds the grid column it sits in.** v1's asked
   for 680px and was given 552px, so large type broke into ragged lines on
   desktop, not just on phones. Measure the *rendered* box, not the class.
4. **Text that is transparent by design.** Gradient-clipped headings vanish
   entirely in forced-colours modes, which drop background images. Same failure
   family as an entrance animation that never runs: the fallback must be the
   visible state. v1 solved it by abandoning the gradient (see below).
5. **Overlay menus that are only a visual.** A disclosure owes: focus in on
   open, focus back to the toggle on close, Escape to dismiss, Tab cycling
   inside it, and no scrolling of the page underneath. v2's `mobile-menu.tsx`
   and v3's `header-nav.tsx` were not audited for this — do it.
6. **Form feedback that declares both `role="alert"` and `aria-live="polite"`.**
   Contradictory. Also check the failed field is marked `aria-invalid`, is
   described by the message, and actually receives focus. All three variants
   share the same mailto form shape, so all three likely share the fault.
7. **No skip link, and anchor targets sitting under the sticky header.**

## The scroll-margin arithmetic

Worth writing down because getting it wrong is invisible in code review and
obvious on screen. After an anchor jump:

```
gap below header = scrollMarginTop + sectionPaddingTop − headerHeight
```

v1 has been through this twice, which is the point of writing it down:

| Section padding | Scroll margin | Gap below header | Verdict |
| --- | --- | --- | --- |
| 80 | 80 (`scroll-mt-20`) | 91 | Read as a layout fault |
| 80 | 32 (`scroll-mt-8`) | 43 | Read as deliberate |
| 96 | 16 (`scroll-mt-4`) | 43 | Current, after the spacing pass |

The third row is the lesson. Loosening the section rhythm from 80 to 96 silently
changes where every anchor lands; the margin had to come down by the same 16px
to hold the gap at 43. **The margin is a function of the padding, not a value in
its own right.** Change one without the other and every in-page jump is wrong by
exactly the difference, which nobody notices in a diff.

**Re-measure per variant** — v2 and v3 have different header heights and may have
different section padding. Do not copy `scroll-mt-4` across on faith.

Verification trick: change the margin, then check the scroll position moves by
exactly the difference between old and new. If it moves by something else, the
target is not the element you think it is.

`scroll-behavior: smooth` is already **global** in `app/globals.css`, at the
user's direction, so v2 and v3 inherit it with no work. Only the landing
position needs per-variant attention.

## Motion patterns established, and how to reuse them

- **Staggered reveals.** `.reveal reveal-step` plus an inline `--i` per card.
  Offsets each card's `animation-range` so a row sweeps instead of arriving as a
  block. `.reveal-step` is variant-neutral already — reuse as is.
- **Header lift on scroll.** `.v1-nav-lift`, a scroll timeline with **no `from`
  keyframe**, so the resting style is the flat header and a browser without
  scroll timelines simply shows that. Copy the technique, not the class; give
  each variant its own shadow colour.
- **One focus ring per layout**, scoped by a root class on the layout wrapper
  (`.v1-root`). v2 and v3 have no equivalent and currently fall back to the
  browser default in most places.
- **Everything sits inside the existing guards**: `prefers-reduced-motion:
  no-preference` and, for scroll-driven work, `@supports (animation-timeline:
  view())`. Do not add motion outside them.

## Design devices taken from e.gov.ph

Reviewed at the user's request. The site sells a consumer phone app; v1 sells
professional services. The mechanics transfer, the tone does not.

- **Two-tone headline.** Each heading closes with its payoff phrase in the
  accent colour. This *replaced* v1's gradient headline and so deleted the
  forced-colours special case with it — a net removal, which is why it was the
  best of the four.
  **Per-variant caveat:** v1 uses orange, except on the deep green section where
  orange goes muddy and the section's own peach is used instead. Pick the accent
  per background, not once globally.
- **Connected step nodes.** A hairline between the first and last node centres
  (a sixth in from each edge in a three-column grid), fading at both ends,
  hidden once the columns stack. The node needs `relative` and an opaque
  background in the section's own colour, or the rule strikes through it.
- **Icon ramp.** `color-mix(in oklab, <brand A>, <brand B> calc(var(--i) * 10%))`
  driven by the card index. Because every tint is a blend of two brand colours,
  the ramp cannot drift off-brand however many cards are added. Directly
  reusable with each variant's own pair.
- **Pointer spotlight.** `SpotlightCard` writes the cursor position to two
  custom properties; CSS draws the gradient, so a mousemove re-renders no React.
  Gated on `hover: hover`, or a touch device lights a card and leaves it lit.
  **It currently lives in `modules/v1-classic/components/`. If v2 or v3 want it,
  promote it to `components/ui/` rather than copying it.** The same applies to
  `.v1-spotlight` and `.v1-icon-tint`, which are v1-named but variant-neutral in
  substance.

## What was deliberately not copied from e.gov.ph

Re-decide these only with a reason, not by default.

- **Their reveal mechanism.** Framer Motion writes inline `opacity: 0` on every
  below-fold element and waits on an observer. That is the exact pattern that
  left our own hero blank in a background tab. v1's scroll-driven CSS costs no
  JavaScript and fails to *visible*.
- **Their reduced-motion story.** Their stylesheet contains no
  `prefers-reduced-motion` rules at all.
- **Their rendering model.** One client bundle, no server HTML. Keep variants
  prerendered; pass card contents as `children` so a client wrapper does not
  drag the content across the boundary.
- **A hero stat line** ("40M+ downloads"). We have no verified figures for
  SERBIZ and the project rule forbids inventing them. The slot is ready if the
  client supplies a client count.

## Testing: what was worth a test and what was not

v1 went from 7 tests to 27; the suite overall from 38 to 58. The split is the
reusable part:

- **Red-green on real seams:** validation reporting *which* field failed, the
  form moving focus to it, the menu's Escape / focus / trap / scroll-lock
  behaviour, and `SpotlightCard` writing the pointer position.
- **Regression guards, written knowingly after the fact:** the permits section
  rendering a labelled placeholder rather than implying a scan exists. These
  passed on first run. That is fine as a guard but it is *not* TDD, and it was
  reported to the user as such rather than dressed up.
- **Not tested at all:** responsive classes, colour ramps, gradients, connector
  geometry. No behavioural seam; asserting Tailwind class strings would be a
  change-detector. These were verified in the browser at 375px and 1440px.

## Gotchas that will recur

- **A JSX comment cannot sit between `return (` and the root element.** It reads
  as a second child and is a parse error, not a lint warning.
- **Programmatic `.focus()` does not reliably match `:focus-visible`.** Send a

- **A hidden Browser pane reports zero for every `getBoundingClientRect()`** and

  back all zeros, check `document.hidden` before believing them.
- **The Browser pane's coordinate frame is not the emulated viewport.** At

- **A sibling overlay paints above non-positioned content**, so the spotlight
