## v1 sideways scroll on phones

Branch `fix/v1-mobile-sideways-scroll` off `origin/develop`.

### What shipped

- `app/8sfz8dn5ts/layout.tsx`: the `v1-root` wrapper carries `overflow-x-clip`.
- `app/8sfz8dn5ts/layout.test.tsx`: renders the layout and asserts the clip
  class. First test under `app/`; it mocks `next/font/google`, which is not
  callable outside the Next compiler.

### Root cause

Two entrances park elements past the right edge of the viewport before
sliding them in: the hero photo (`.enter-x`, `--from-x: 56px`, plus the orange
block hanging 12px further) and each FAQ card (`.reveal-x`, `--from-x: 48px`).
A transformed element still counts toward the document's scrollable area, so
on a 440px phone the page was 484px wide on first paint and 464px wide until
the FAQ revealed. The page could be dragged sideways, and mobile Chrome widened
its layout viewport to match, which made the sticky nav look narrower than
the screen. Desktop never showed it because the wide margins swallowed the
offsets.

### Why clip and not hidden

`overflow-x: hidden` would make the wrapper a scroll container and unstick the
nav. `clip` only clips paint and scrollable overflow, so the sticky nav and the
fixed menu overlay are untouched. Checked in the in-app browser at 440px:
scroll width stays 440 across the whole page, nav sticks at full width.

### Gotcha

`vi.mock("next/font/google", ...)` is needed for any test that imports a
module calling the font loaders. Return `{ variable, className }` from each.
